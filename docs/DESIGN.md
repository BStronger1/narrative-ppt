# 产品设计

## 场景契约

新增 brief 保存场景、时长与重点，进入大纲和正文提示词。需求不属于事实，不能作为可引用材料。答辩场景强调背景、问题、方案、实现、结果、不足，区分已完成内容与后续计划。

答辩场景以来源事实为优先，不要求最低字数或块数。材料不足时允许留白和明确的待补充项；质量报告保留内容稀疏提示，但不会据此触发自动扩写，只有结构错误触发修复。此策略减少补写压力，并非模型事实正确性的保证。

## 证据链

每条大纲要点保存 point、kind、ref、quote。kind 为 source / inference / missing。服务器核对引用存在且摘录出现在原文中（忽略空白）；无效条目保守降级为 missing。页级 source_refs 延续原有契约，供正文生成读取上下文。

按要点原文绑定，避免另一条结论继承旧引用。前端即时失效，保存时服务端重算。来源只从当前项目材料中取，项目权限仍由 OwnedProject 校验。

大纲、编辑器来源面板与 PPTX 备注展示相同的证据。正文扩写没有逐句绑定，界面明确提示复核。摘录匹配不是事实核验，也不证明语义蕴含。

## 过期控制

brief 纳入大纲输入指纹；材料或设置改变后，确认旧大纲会返回冲突。历史无 brief 记录保留兼容路径。补充材料只在大纲未确认时追加，防止输入和页面静默错配。

## 演示与真实模式

真实模式复用结构化生成、页级并发、校验与导出。演示模式使用确定性的材料摘录生成器，其他层仍走实际实现；界面持续展示标识，不将演示输出当作模型效果评测。

## 验证口径

测试覆盖无效摘录、主题不可作为证据、修改要点失效、需求变更使大纲过期及生成导出流程。真实 API 单案例验收见 VALIDATION.md；没有真实用户效率提升或模型引用正确率的系统评测，不应将这些写成简历业绩。

后续可用固定材料集评测引用有效率、人工判定的结论支持率、缺失材料识别率与生成成功率。当前版本不等同于 RAG、OCR、事实核验或多 Agent 系统。
