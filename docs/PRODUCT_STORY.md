# 从心理学设计到 LLM 工作流：让 AI 先考虑听众，再生成 PPT

同一份项目材料，面向评审时需要讲清证据与局限，面向入门听众时需要解释概念，面向技术同行时需要交代约束和取舍。NarrativePPT 想解决的是：怎样把这些沟通要求变成生成流程的一部分。

## 起点：师兄提醒我，先想清楚听众期待什么

项目早期的叙事偏向“背景—问题—方案”。师兄提出建议：这种结构比较适合学术场景，应用可以预设不同听众，参考心理学理论，先考虑他们需要怎样的讲述方式，再生成 PPT。

这成为一次具体的产品调整：让用户先提供听众、知识基础、沟通目标和时长，模型先规划全篇叙事，再生成大纲和页面。系统目前已部署运行，并在课题组中使用；对外提供的是免登录成果预览，生成自己的内容仍需部署。课题组使用状态来自维护者说明，尚未形成量化使用或效果报告。

## 三类理论，分别约束一个设计问题

以下是本项目对理论的设计应用，不是原论文验证过的 PPT 生成方法。

| 参考 | 设计时要问的问题 | 已落到系统中的要求 |
|---|---|---|
| [认知负荷理论：Sweller, 1988](https://doi.org/10.1207/s15516709cog1202_4) | 听众有哪些已有知识？这一页是否要求他们同时理解太多新概念？ | 接收知识基础与密度设置；Prompt 要求新术语先解释、按问题分段；每页围绕一个重点，并分配讲述时间。 |
| [多媒体学习：Mayer & Moreno, 2003](https://doi.org/10.1207/S15326985EP3801_6) | 标题、文字和图形是否在帮助听众理解同一件事？ | 用标题提示重点；按观点、对比、过程、数据安排页面任务；在提示词与版式规则中要求图文对应，材料不足时保留留白。 |
| [精细加工可能性模型 ELM：Petty & Cacioppo, 1986](https://doi.org/10.1016/S0065-2601(08)60214-2) | 听众有什么沟通任务、知识基础和处理条件？需要多深的论据？ | 把目标、重点与知识基础传入叙事规划；需要审议的内容保留依据、替代方案和局限；用户补充要求优先于预设。 |

认知负荷研究提醒设计者考虑有限的认知处理能力与已有知识；多媒体学习研究讨论文字与图形的组织及认知过载；ELM 讨论加工动机、能力和说服过程的关系。这里没有实时测量听众的认知负荷或加工动机，目标和知识基础只是用户提供的设计输入。

特别是 ELM，不能被简化为“专家看逻辑、外行看情绪”。系统也不会凭职业预测心理：六类预设是可修改的任务假设，知识基础和用户要求优先。

## 用同一个项目，说明讲述顺序为什么需要变化

以一个软件原型为例，下表展示代码中的预设逻辑，**不是三组模型实测输出，也不是用户效果实验**。

| 听众与任务 | 默认从哪里讲起 | 需要保留什么 |
|---|---|---|
| 学术评审：判断研究是否成立 | 研究问题 → 已有认识与缺口 → 方法与取舍 | 结果证据、贡献和局限 |
| 技术同行：评审实现方案 | 约束与目标 → 方案与替代方案 → 关键机制 | 验证方法、故障边界和适用条件 |
| 入门听众：理解一个新概念 | 熟悉情境 → 必要概念 → 分步解释 | 例子、边界和可尝试的问题 |

另外提供管理者、投资/业务评审及自定义听众，共六类。管理者预设从待决事项切入，是本项目的产品选择，不能说成心理学论文证明了“管理者一定喜欢结论先行”。

## 把设计要求变成可审阅的中间结果

只在系统提示词里写一句“结合心理学”，很难看出模型是否考虑了听众。因此，NarrativePPT 先要求模型给出结构化叙事计划：

- 听众需求、全篇主线、开场及 3–7 个阶段；
- 收尾行动、页面视觉策略、简短设计理由；
- 待确认假设，以及逐页角色、建议用时和衔接。

用户可以查看和重新规划。AI 规划无效时会标明预设回退，不把预设内容标成模型分析。讲述时间是排练参考，不是实际演讲耗时预测。

LangGraph 编排大纲的 `prepare → plan → generate`，并组织逐页生成工作流；LangChain 负责模型调用，Pydantic 约束输出结构。听众、时长和叙事计划进入后续生成上下文。这里使用有明确步骤的 LLM 工作流，没有多个自主 Agent 协商。

实现：[大纲编排](../backend/app/workflows/outline.py) · [逐页编排](../backend/app/workflows/slide.py) · [结构化调用](../backend/app/llm/client.py)

## 故事要讲得清楚，也要能生成、能核对

产品设计落到真实模型调用后，又遇到两个工程问题。

**长大纲会超时，也会输出不合规结构。** 最初 5 页通过，10–20 页在大纲读取阶段失败。采用全篇规划、每批最多 5 页、两批并发后，第一轮仍出现页数和证据类型错误。随后补充精确 Schema、业务校验、失败批次局部重生成和超时预算。局部重试保留的是同次运行中已成功的批次；尚未实现跨任务重启的断点续跑。

**叙事合理不等于论据可靠。** 模型输出中的材料摘录需要匹配校验，并区分来源、推断和待补内容。旧证据绑定大纲要点文本；要点变更后，不再沿用原来的有效证据标记。页面正文编辑仍需人工复核，不宣称任何文字改动都会被自动事实核验。

模型通过 OpenAI 兼容接口接入，用户可配置自己的模型与 API Key；配置按账号隔离，密钥加密保存。最终导出可编辑 PPTX，并保留来源与讲述备注，方便用户继续审阅。

## 现在能证明什么，接下来验证什么

2026-10-06，使用 `DMXAPI-deepseek-v4-flash`，对同一份合成材料、学术听众完成 5 / 10 / 15 / 20 页生成及 PPTX 结构回读。四档均完成，质量提示仍有 3 / 7 / 8 / 14 条。同版本地后端回归 442 项通过、3 项跳过，包含既有与新增测试；前后端 GitHub CI 通过。

这些证据支持“流程能在这组条件下完成”，不能证明“听众理解得更好”。课题组中使用也不等于已经完成效果实验。目前还没有阅读理解、记忆、说服效果或节省时长的对照测量。

下一步可评估：针对同一材料与目标听众，比较普通生成和听众规划两种流程，先记录大纲适配性、人工修改量和实际理解表现。实验方案、样本量和评价标准尚未确定，不把这项计划写成已完成结果。

如果你愿意试用，最有价值的反馈是：**你给谁讲、希望他们理解或决定什么，以及哪一页最需要改。**
