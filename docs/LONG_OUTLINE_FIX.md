# 长页数生成修复与真实验收（2026-10-06）

## 问题与修复

此前 DeepSeek 与 Gemini 的 10、15、20 页验收均在大纲阶段失败，底层错误链包含 `APITimeoutError → ReadTimeout`。这证明当时配置下发生模型读取超时，不能证明模型本身不支持长 PPT。

本次恢复使用 `DMXAPI-deepseek-v4-flash`，并部署以下调整：

- 超过 5 页时，先生成完整的简短页序，再每批扩展最多 5 页，同时最多请求 2 批。每批都带全篇结构和页码，合并时保持原始顺序。所有批次通过页数、布局和来源检查后才保存；失败时取消其他未完成批次。
- 每批明确列出分配到的页面，并在 JSON Schema 中约束精确页数、布局枚举和来源编号。格式或业务校验失败时只重生成该批一次，已成功批次保留；错误诊断只记录页码范围和固定原因代码。
- 模型读取等待从 60 秒调整为 180 秒，连接建立最多等待 10 秒。SDK 最多重试 1 次，减少嵌套重试的等待放大。
- 每次大纲工作流最多等待 600 秒，在后台任务的 900 秒硬超时之前捕获失败并更新项目状态；后台最多运行 2 次。验收脚本的大纲观察窗口为 1320 秒，覆盖任务重试及排队余量。增加观察窗口本身不算修复成功，仍要求真实完成大纲、正文和导出。
- 区分超时、连接、鉴权、限流/额度、请求兼容性与输出结构错误。鉴权和请求拒绝不进行后台重复尝试；用户提示不包含供应商响应正文、密钥或输入材料。
- 进度区分听众叙事规划和逐页大纲生成。本次没有前端代码变更。
