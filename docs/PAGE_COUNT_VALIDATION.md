# 不同页数真实模型验收（2026-10-06）

本页保留修复前的失败记录。后续 DeepSeek 修复和复测见 [长页数生成修复](LONG_OUTLINE_FIX.md)。

## 方法

- 环境：turing 已部署版本；真实模式，数据库与 Redis 健康。
- 模型：DMXAPI-deepseek-v4-flash，通过独立验收账号的个人模型设置调用，先验证连接。不是演示模式。
- 固定材料：`backend/scripts/fixtures/page_count_source.txt`，同一份虚构校园失物招领案例，原文件 1,805 字符，解析后正文 1,760 字符。没有使用真实用户数据。
- 固定学术听众与简洁密度，分别请求 5、10、15、20 页；目标讲述时长分别为 5、10、15、20 分钟。
- 验证上传、AI 叙事、大纲页数、时间预算、逐页完成、质量报告、PPTX 回读页数、可编辑文字和来源/讲述备注。每档单次发起，保留服务本身的重试；不把四个样例当作统计成功率。
- 脚本：`backend/scripts/test_page_counts.py` 与参数化的 `test_live_api.py`。每档独立保存结果，退出时清除测试账号的个人密钥；未手工改写生成结果。

## 已发现的问题

1. 10 页、15 页、20 页的服务日志出现 `APITimeoutError → ReadTimeout`，均发生在大纲调用。当前模型读取超时配置为 60 秒。证据能确认请求读取超时，不能据此断言服务商内部原因；延长等待或拆分长大纲生成需要另行修改并复测。本轮没有修改生成逻辑或超时配置，未完成这些问题的修复。
2. 5 页质量报告有 7 条 warning、0 条阻断 error：3 处文字/要点可能溢出，3 条简短内容或占位措辞提示，1 条推断审查提示。第 2 页导出 XML 包含自动缩字设置，两处字号缩放约 75.9%；这不等同于 PowerPoint/WPS 实际阅读效果通过。
3. 长任务的进度描述较笼统，不能区分叙事规划与大纲生成等待；较长等待仍需改善。

## 补充检查与边界

- 服务器对 4 页、21 页创建请求返回 422，并明确指向 `page_count` 字段。新建范围是 5–20 页；本轮没有覆盖编辑后 1–40 页的全部操作。
- 新增 8 项确定性回归，覆盖 5/10/15/20 页与 1/20 分钟组合，全部通过，验证页数和讲述时间分配。它们使用演示生成器隔离流程逻辑，不能替代上述真实模型验收。
- 本轮未重新运行此前的完整 416 项通过、3 项跳过回归；不能把新增 8 项与历史结果相加称作一次新的完整回归。
- 本轮只覆盖一个模型、同一份材料、一个听众设定，不是多模型兼容性测试、并发压测或人工视觉评测。
- 原始报告和日志位于被忽略的 `backend/var/live-validation/page-counts-20261006/`；失败记录保留，不以重跑覆盖。
- 四档测试账号的个人密钥均已在结束时清除。[5 页真实模型样例](../examples/page-counts-20261006/5-pages.pptx)保留原始输出，仍需审阅质量提示。

## 复现

在已配置真实模型、API 和 worker 的环境中，从 backend 目录执行（消耗 API 额度）：

```bash
python scripts/test_page_counts.py --url http://127.0.0.1:39800 --output-dir var/live-validation/page-counts-new-run
```

输出目录必须是新的目录，避免覆盖已有验收证据。
